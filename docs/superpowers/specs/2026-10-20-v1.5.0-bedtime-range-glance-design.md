# v1.5.0 — Bedtime preview, graph range, glance intake bar

Date: 2026-10-20
Status: design approved in chat, spec awaiting review

## Goal

Three small additions that help the user decide whether to have another drink
and read their day at a glance, without new screens or settings:

1. **Bedtime preview** — the Add Drink menu shows, for each preset, the total
   caffeine at the next bedtime if that drink is taken now.
2. **Graph range** — the Timeline graph cycles between three time windows.
3. **Glance intake bar** — the glance shows today's intake against the daily
   limit as a thin bar.

Success: each feature works on button-only and touch watches, fits on the
smallest supported screens (fenix6, fr255s) in all five languages, and the
fenix6 glance and full-view memory stay within a few hundred bytes of v1.4.0.

## Out of scope

- Custom mg entry on the watch; editing a dose's mg or name.
- A phone setting for the graph range.
- Bedtime preview anywhere other than the Add Drink menu (no toast, no Summary line).
- Glance changes beyond the bar (no bedtime line, no live countdown — the
  system decides when the glance redraws).

## 1. Bedtime preview in the Add Drink menu

### Behaviour

Each `MenuItem` sub-label changes from `64 mg` to `64 mg · bed 38 mg`
(English). The second number is the projected **total** level at the next
bedtime: the current doses decayed to bedtime, plus this preset taken now,
decayed to bedtime. It compares directly with the 50 mg sleep-safe threshold.

Bedtime is `Util.getBedtimeEpoch(now)`, which already rolls forward to the
next day once today's bedtime has passed. After bedtime the preview therefore
refers to tomorrow night and will usually be small; this is accepted, no
special case.

The values are computed once when the menu opens (`SummaryDelegate.onSelect`).
The menu is short-lived; no refresh.

### Model

New public method on `CaffeineModel`:

```
// Level at atEpoch if an extra dose of mg were taken at doseEpoch.
// Pure: does not modify _doses.
function getLevelWithDose(atEpoch, mg, doseEpoch)
```

Returns `getCurrentLevel(atEpoch) + decayedAmount(mg, doseEpoch, atEpoch)`;
the extra term is 0 when `doseEpoch > atEpoch`. Uses the injected half-life,
like every other model method.

### Strings

New row in `translations/en.csv`:

| key | where | max | sample | english |
|---|---|---|---|---|
| `MenuBedPreview` | watch | 20 | `999\|999` | `$1$ mg · bed $2$ mg` |

Context for translators: "Add Drink menu, under each drink name. $1$ = the
drink's caffeine, $2$ = total caffeine expected at bedtime if you have it now."

`SummaryDelegate` loads the template once per `onSelect` (the menu is built
there) and fills it with `Lang.format(tpl, [preset[:mg], Util.formatMg(bedMg)])`.
Finnish goes to the translator through the shared sheet; cs/de/fr get drafts
and stay labelled unreviewed.

## 2. Timeline graph range

### Behaviour

SELECT on the Timeline cycles the window: **4h → 8h → 12h → 4h**. A tap
reaches `onSelect` first on touch watches, so the same handler covers it.

| Range | Past | Future | Sample step |
|---|---|---|---|
| 4h  | 2h | 4h  | 10 min (37 samples) |
| 8h (default) | 4h | 8h  | 15 min (49 samples, as today) |
| 12h | 6h | 12h | 20 min (55 samples) |

The axis labels (`-Nh`, `now`, `+N/2h`, `+Nh`) already derive from the window,
so they show the active range; no extra title label or new string. (This
replaces the "8h next to the title" idea from the chat design: the Finnish
title plus a range suffix would exceed the 20-character limit, and the labels
already say the same thing.)

The choice persists in `Application.Storage` under `timelineRange` (index 0–2).
A missing or out-of-range value falls back to index 1 (8h).

### Code

- `TimelineView`: replace `PAST_HOURS` / `FUTURE_HOURS` / `SAMPLE_INTERVAL_MIN`
  constants with instance fields set from the stored index in `onUpdate`
  (via a small static table `RANGES = [[2, 4, 10], [4, 8, 15], [6, 12, 20]]`).
  `minutesToX`, `drawBedtimeMarker`, `drawDoseMarkers`, `drawNowMarker` and
  `drawTimeLabels` read the fields instead of the constants. Add
  `cycleRange()` that advances the index, stores it, and calls
  `WatchUi.requestUpdate()`.
- `TimelineDelegate`: hold a view reference (like `LogDelegate`), add
  `onSelect()` → `view.cycleRange()`; return `true`. `SummaryDelegate` and
  `LogDelegate` construct it with the view.
- Range lookup and wrap-around live in a pure helper so they can be unit
  tested without a view (e.g. `Util.nextTimelineRange(index)` and
  `Util.timelineRangeIndex(stored)`).

## 3. Glance intake bar

### Behaviour

A thin horizontal bar (3 px; 2 px where the glance is under 60 px tall)
between the big number and the status line, full glance width. Track in
`Colors.TRACK`; fill proportional to `today's intake / daily limit`, clamped
to full. Fill colour matches the Summary screen's bar:

- below 80 % of the limit: `Colors.ACCENT`
- from 80 %: `Colors.WARNING`
- at or above the limit: `Colors.DANGER`

With no drinks today the track alone is drawn.

### Code

- `GlanceView.onUpdate`: `model.getDailyIntake(now)` — the glance already
  loads doses back to `getOldestCountedTime(now)` (at least 30 h), which
  covers today since local midnight.
- New `Util.getDailyLimit()` (Util is already `(:glance)`): reads the
  `dailyLimit` property, defaults to 400, treats values ≤ 0 as 400. Use it in
  `GlanceView` and `SummaryView` (which today repeats the same null check).
  `AlertManager`, `HistoryView` and `DayDetailView` read the property inline;
  switching them over is optional cleanup, done only if it stays trivial.
- Bar position: between `numY` (32 %) and the status line (72 %); exact `y`
  chosen so it clears both text lines on fenix6 (smallest glance) and
  vivoactive5. No new strings.

## Testing

Unit tests (`pwsh tools/run-tests.ps1`):

- `CaffeineModelTest`: `getLevelWithDose` with no existing doses (equals the
  single dose decayed), with existing doses (sum), with `doseEpoch == atEpoch`
  (full mg), with `doseEpoch > atEpoch` (extra term 0); `_doses` unchanged
  afterwards.
- `UtilTest`: `nextTimelineRange` wraps 2 → 0; `timelineRangeIndex(null)`,
  `(-1)`, `(3)` return 1; `getDailyLimit` defaults.

Simulator (`tools/sim-matrix.ps1`, en and fi; fr255s, fenix6, vivoactive5,
fenix9pro51mm):

- Add Drink menu sub-label fits in all languages.
- Timeline at all three ranges: labels readable, no overlap, bedtime marker
  where expected.
- Glance bar clears the number and the status line; colours at 0 %, 85 %,
  110 % of limit.

Memory: fenix6 release build, glance and Summary → Add Drink menu → Timeline,
compared with v1.4.0 (glance 17.6 / 27.9 kB, summary 41.7 / 59.9 kB).
