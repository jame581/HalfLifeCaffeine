# v1.6.0 Safe-Sleep Clock Time Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the safe-to-sleep moment as a clock time by default (countdown as a setting), make every time of day follow the watch's 12h/24h setting, and turn the fixed 50 mg sleep-safe level into one sanitised setting (25–100 mg).

**Architecture:** Pure helpers in the `(:glance)` `Util` module (sanitising, clock formatting, which safe-sleep line to show) carry the logic and the tests; views and `AlertManager` call them. Two new Properties, settings in `settings.xml`; the sleep level also on the companion page and in the `settings` message.

**Tech Stack:** Monkey C / Connect IQ SDK 9.x, `Toybox.Test` via `pwsh tools/run-tests.ps1`, translation sheets via `pwsh tools/build-translations.ps1`, HTML/JS companion page.

**Spec:** `docs/superpowers/specs/2026-11-23-v1.6.0-sleep-clock-time-design.md`

## Global Constraints

- Properties: `sleepTimeFormat` number default `0` (0 = clock, 1 = countdown); `sleepSafeMg` number default `50`, range 25–100.
- Every user-visible string is a row in `translations/en.csv`, then `pwsh tools/build-translations.ps1 -Sync`; never edit generated `strings.xml` or the companion `I18N` block by hand. Rows with `$1$` need a `sample`; a literal sample (`10:07 PM`) is fine, the generator only replaces `{duration}`/`{month}`.
- Strings drawn in the glance need `glance` in `where`. Views load strings in `initialize()`, never in `onUpdate`.
- `Util` stays free of resource loading: callers pass strings in.
- Drawing coordinates are integers. Templates use `Lang.format`, never concatenation.
- Missing or bad property values fall back to defaults (users updating from v1.5.0 have neither property).
- Finnish blocks the store release; development runs on the English fallback (`WARNING` lines from the generator are expected until `fi.csv` is filled).
- Tests: `pwsh tools/run-tests.ps1` exits 0. Build check per task: `& $mc -f monkey.jungle -d vivoactive5_sim -y D:/Garmin/Key/developer_key -o bin/CoffeTracker.prg -w -r` (with `$mc` resolved as in CLAUDE.md) succeeds.

## Review Focus

1. **User upgrading from v1.5.0** (both properties null) → clock mode, 50 mg; pinned by `testSanitizeSleepSafeMg` (null) and `testSleepTimeFormatDefault` in Task 1.
2. **Level above 1 mg but already under a raised/lowered threshold** → `Clear`, not "Safe at <now>"; pinned by `testSafeSleepKind` (minutesToSafe 0) in Task 4.
3. **12h edge hours** — 00:05 → `12:05 AM`, 12:00 → `12:00 PM`, 09:03 → `9:03 AM`; pinned by `testFormatClock12h` in Task 3.
4. **Phone sends `sleepSafeMg` as a string, Float or out of range** → stored value is a clamped whole number or untouched; pinned by `testPhoneSleepSafeMg` in Task 5.
5. **Setting changed while the full view is open** → next redraw uses it; no view or `AlertManager` caches the level or format in `initialize()` (reviewer check in Task 2 and Task 4; `onUpdate`/`checkSleepAlert` read through `Util` each call).
