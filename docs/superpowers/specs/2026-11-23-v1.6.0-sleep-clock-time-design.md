# v1.6.0: Safe-sleep clock time, 12h clock, sleep level setting

Date: 2026-11-23
Status: approved 2026-11-23

## Why

User feedback: *"Have you considered displaying the safe sleep time there? Now I
always have to calculate the hours from my watch to see how long it lasts…
instead of showing how many hours and minutes… it would show something like
22:07."* The countdown ("Sleep safe in 3h 20m") makes the user add it to the
current time in their head. What they actually want to know is when they can go to bed.

While reading the code for this, three related gaps came up and are in scope:
times ignore the watch's 12h setting, the 50 mg safe-to-sleep level is
written out in three places, and that level is fixed.

## Goals

1. **Safe-sleep as a clock time, by default.** The main screen shows
   `Sleep safe at 22:07`, the glance `Safe at 22:07`. A phone setting switches
   both back to the countdown (`Sleep safe in 3h 20m` / `Safe in 3h 20m`).
2. **Times follow the watch's 12h/24h setting** everywhere a time of day is
   shown: the safe-sleep line, Log rows, Day Detail rows.
3. **One sleep-safe level in code.** `AlertManager`, `GlanceView`,
   `SummaryView` and `TimelineView` read it from one helper, not four literals.
4. **Sleep-safe level is a user setting**, 25–100 mg, default 50. It controls
   the main-screen line, the glance line, the safe-to-sleep vibration and the
   Timeline's existing dashed threshold line.

Success: works on button-only and touch watches, the new lines fit on the
smallest screens (fenix6, fr255s) in all five languages and in 12h mode, the
glance and full-view memory on fenix6 stay within a few hundred bytes of
v1.5.0, and all tests pass.

## Non-goals

- Changing the safe-sleep search (still 1-minute binary search over 24 h).
- A *new* sleep-level marker on the Timeline graph (the existing dashed line
  just follows the setting).
- Putting the display-format setting on the companion page (see Approaches).
- Changing how often the glance redraws (the system decides that).

## Anti-goals

- Existing users losing their settings or seeing a broken line after the
  update (missing properties must fall back to the defaults).
- A clock time that misleads: showing a time when the level never drops below
  the threshold within the search window.
- Hard-coded English: every new word goes through the translation sheets.

## Approaches (for where the settings live)

- **A. Garmin Connect settings only** (`settings.xml`, like `theme`). Smallest;
  but users who configure through the companion page wouldn't find the sleep
  level next to half-life and daily limit.
- **B. Both in Garmin Connect; sleep level also on the companion page and in
  the phone→watch `settings` message.** *Chosen.* The sleep level belongs
  with half-life / daily limit / alerts, which the companion already mirrors;
  the display format is a taste setting like `theme` and stays Garmin-only.
- **C. Both everywhere.** Most uniform, but a companion dropdown for a
  set-once preference isn't worth the extra page and message surface.

## Design

### Settings

Two new `Application.Properties` (`resources/properties.xml`):

| id | type | default | meaning |
|---|---|---|---|
| `sleepTimeFormat` | number | `0` | 0 = clock time, 1 = countdown |
| `sleepSafeMg` | number | `50` | safe-to-sleep threshold, mg |

`resources/settings.xml`:
- `sleepTimeFormat` as a `list` (entries "Clock time" / "Countdown"), placed
  after the safe-to-sleep alert switch.
- `sleepSafeMg` as `numeric`, `min="25" max="100"`.

Helpers in `Util` (module is `(:glance)`, so both processes get them):
- `Util.getSleepSafeMg()` — reads `sleepSafeMg`, falls back to 50 when null or
  not a number, clamps to [25, 100], rounds to a whole number. A pure
  `sanitizeSleepSafeMg(value)` sits under it for tests (same shape as
  `sanitizeDailyLimit` / `getDailyLimit`).
- `Util.getSleepTimeFormat()` — 0 unless the property is exactly 1.

The 50 mg literals go: `AlertManager.SLEEP_SAFE_MG`, `GlanceView.mc:41`,
`SummaryView.mc:46` and `TimelineView` (`drawThresholdLine`'s `50.0`, and the
`_maxMg = 50.0` scale floor) all use `Util.getSleepSafeMg()`. *Builder call:*
the graph's scale floor becomes the threshold itself, so the dashed line
always fits even at 100 mg with no drinks. CLAUDE.md's "Sleep-safe
threshold: 50mg" invariant is updated to name the setting and the helper.

### Companion page and sync

- `companion/settings/index.html`: a number input `sleepSafeMg` (min 25,
  max 100, step 5, default 50) near the half-life field, with a label and a
  short help line from the sheets; pre-filled by `applyIncomingSettings` and
  saved in `saveSettings()` exactly like `halfLifeHours`.
- How it reaches the watch: the page saves through `ciq://settings?…`, which
  the Connect IQ mobile app turns into Properties, not necessarily through
  `handlePhoneMessage`. So **the guarantee is clamp-on-read**:
  `Util.getSleepSafeMg()` sanitises on every read, and a bad stored value can
  never reach the views or the alert. The page clamps to 25–100 before saving
  too.
- For parity with the other fields, `SyncManager.handlePhoneMessage` also
  accepts an optional `sleepSafeMg` in a `settings` message and stores it.
  Messages without it change nothing. Its test covers that path only.
- CLAUDE.md's protocol section lists the new field and notes that the
  companion saves via `ciq://settings`.

### Time-of-day formatting (12h fix)

`Util.formatTime(epoch)` becomes `Util.formatTime(epoch, am, pm)` and is 12h/24h aware:
- reads `System.getDeviceSettings().is24Hour`;
- 24h: `22:07` (unchanged);
- 12h: `10:07 PM`, hour without leading zero, 12 for noon/midnight; the
  AM/PM suffixes come from sheet rows `TimeAM` / `TimePM` (glance-scoped,
  English "AM" / "PM").
- A pure `Util.formatClock(hour, min, is24, am, pm)` does the work and is
  unit-tested; `formatTime` passes in the device setting and the suffixes.
  Because `Util` must stay free of resource loading, callers that render
  times load `TimeAM`/`TimePM` once in `initialize()` and pass them in
  (`formatTime(epoch, am, pm)`); LogView, DayDetailView, SummaryView and
  GlanceView each load them once.

Log and Day Detail rows already go through `RowFit.line`, which cuts the drink
name to fit; on a 12h watch the longer time takes a few characters from the
name. Accepted.

### Safe-sleep line

Both views compute `minutesToSafe = model.getMinutesToSafe(now, Util.getSleepSafeMg())`
as today, then:

| state | clock mode (0) | countdown mode (1) |
|---|---|---|
| level < 1 mg, or minutesToSafe == 0 | `Clear` | `Clear` |
| 0 < minutesToSafe < 1440 | `Sleep safe at $1$` with `formatTime(now + minutesToSafe*60)` | `Sleep safe in $1$` (today's) |
| minutesToSafe == 1440 (search cap: never drops in 24 h) | countdown text with `24h+` | `24h+` |

`24h+` is `formatDuration(1440)` + "+" — no new string. Rounding: the clock
time is `now + minutesToSafe*60` truncated to the minute by `formatTime`,
which matches the countdown's minute rounding.

No "tomorrow" marker: the search is capped at 24 h, so any time shown is the
next occurrence of that clock time and can't be confused with a different day.

Fitting: `SummaryView` already steps the font down (`fitFont`); `GlanceView`
already drops to `FONT_XTINY`. Both keep doing so with the new strings.

### Strings (translations/en.csv)

New rows (sheet `max` with `sample` so the checker measures real text):

| key | where | en text | sample |
|---|---|---|---|
| `SummarySleepSafeAt` | watch | `Sleep safe at $1$` | `{time}` worst case `10:07 PM` |
| `GlanceSafeAt` | glance | `Safe at $1$` | `{time}` |
| `TimeAM`, `TimePM` | glance | `AM`, `PM` | — |
| `SettingSleepFormat` | settings | `Sleep time shown as` | — |
| `SleepFormatClock` | settings | `Clock time` | — |
| `SleepFormatCountdown` | settings | `Countdown` | — |
| `SettingSleepSafeMg` | settings | `Safe to sleep below (mg)` | — |
| `CSleepSafeMg` (+ help) | companion | `Safe to sleep below` | — |

If the generator has no `{time}` sample token, add one (worst-case clock text
in that language's AM/PM). **Finnish blocks the release** (decided
2026-11-23): implementation and verification go ahead with the generator's
English fallback, the new English rows are handed to the Finnish translator,
and the store build runs with `-Require fi` once the translation lands.
Czech/German/French drafts follow the existing convention.

### Tests

- `UtilTest`: `formatClock` (24h, 12h noon/midnight/single-digit hour,
  suffixes passed through); `sanitizeSleepSafeMg` (null, string, 10→25,
  200→100, 37.6→38, 50→50); `getSleepTimeFormat` default.
- `SyncManagerTest`: `sleepSafeMg` in a settings message is written and
  clamped; a message without it leaves the property alone.
- A small pure helper for the line choice (e.g.
  `Util.safeSleepKind(level, minutesToSafe)` → clear / time / capped) tested
  for the three table rows, so the views stay thin.

- Version bump in the manifest/store per the usual release steps; What's New in
  `docs/store-listing*.md` (en, cs, fi; de/fr drafts).
- `sim-matrix` pass on vivoactive5, fenix6, fr255s, en/fi/cs, with one 12h
  run to check fitting.
