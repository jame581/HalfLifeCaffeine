# v1.4.0 — Localization (Design)

Date: 2026-10-09
Status: awaiting review

## Goal

HalfLife Caffeine speaks the user's language everywhere they meet it: on the watch, in the phone settings, in the companion page, and on the store listing.

Languages: English (existing), Finnish (community contributor), Czech (Jan), German and French (drafted, unreviewed).

Success means:

- A watch set to one of the five languages shows no English text in any view, menu or the glance, apart from the app name and user-entered drink names.
- A translator can deliver a language without touching Git, XML or HTML.
- Adding a sixth language later is: copy a sheet, fill it in, run one script, add one manifest line.

## Decisions already made

| Topic | Decision |
|---|---|
| Scope | Watch UI, phone settings titles, companion page, store listing |
| Default drink names | Translated once, at first seed, into the watch language at that moment. Existing users' preset lists are never touched. No re-translation when the watch language changes. |
| Release order | v1.3.1 (device support, incl. fenix 9) ships first; this is v1.4.0 |
| Translator workflow | One sheet per language, plus one store-listing text file |
| German / French | Ship drafts in 1.4.0; store listing and README state they are unreviewed and invite corrections |

## Non-goals

- Live re-translation of preset or logged drink names (would change the storage format and sync payload).
- Right-to-left or non-Latin languages.
- Translating the app name, the `mg` unit, or brand drink names (Red Bull, Monster).
- Changing any behaviour, layout structure or the phone protocol.

## Source of truth: `translations/`

```
translations/
  en.csv          master: key, where, context, max, text
  fi.csv          key, where, context, max, english, translation
  cs.csv
  de.csv
  fr.csv
  README.md       one-page instructions for translators
tools/
  build-translations.ps1
```

- CSV, UTF-8 with BOM so Excel shows diacritics correctly. The script accepts both `,` and `;` as delimiter, because Excel in Finnish and Czech locales saves with `;`.
- `where` is one of `watch`, `settings`, `companion`. `context` is a plain-language note ("title of the timeline screen"). `max` is a character limit, set only where the screen is tight.
- `en.csv` is the only place English text is edited. The script copies the current English and context into each language sheet, so a translator always sees up-to-date source text, and marks rows whose English changed since they were translated.
- Generated files are committed. A normal build never needs the script.

### What the script generates

| Output | From rows where |
|---|---|
| `resources/strings.xml` | `watch`, `settings` (English) |
| `resources-fin/`, `-ces/`, `-deu/`, `-fre/strings.xml` | `watch`, `settings` |
| Dictionary block in `companion/settings/index.html`, between marker comments | `companion` |

Sheet-to-resource mapping: `fi → fin`, `cs → ces`, `de → deu`, `fr → fre`.

### What the script refuses

The script exits non-zero and names the offending key when:

- a language is missing a key that `en.csv` has, or has a key `en.csv` does not;
- a translation is empty (a language is only generated and added to the manifest once its sheet is complete);
- a placeholder (`$1$`, `$2$`) present in English is missing or duplicated in a translation;
- a translation exceeds `max`.

## Watch

### Strings

Every user-visible literal in `source/` moves to `resources/strings.xml` and is read with `WatchUi.loadResource(Rez.Strings.X)`. Inventory (about 45 strings):

- Screen titles: Caffeine Timeline, Today's Drinks, History, Add Drink, Edit Drink, Edit Time
- Summary: `mg caffeine`, `Clear`, `Sleep safe in …`, `… / … mg today`, `Press to add drink`
- Glance: `Clear`, `Safe in …`
- Timeline: `now`, `Now: … mg`
- Empty states: No drinks today, No history yet, Details expired after 14 days
- Menus: Edit time, Delete, the seven edit-time offsets
- Duration units used by `Util.formatDuration`
- The 12 default drink names (brand names keep an entry but are not translated)
- Phone settings: the six hardcoded titles in `resources/settings.xml`, plus the existing theme and preset titles

Unused entries in today's `strings.xml` are removed.

Internal identifiers stay as code literals and are not translated: storage keys, property names, menu item ids (`edit_time`, `delete`), alert status values (`ok`, `warning`, `over`), sync payload keys.

### Sentences with values

Strings that embed a value become templates filled with `Lang.format`, because word order differs between languages:

- `Sleep safe in $1$`, `Safe in $1$`, `Now: $1$ mg`, `$1$ / $2$ mg today`
- Day-detail date: `$1$ $2$, $3$` (month, day, year) so each language can reorder

Edit-time offsets are whole strings per entry (`-15 min`, `-1 hour`, `-2 hours`), not assembled from parts, because plural forms differ.

### Dates

`HistoryView` and `DayDetailView` drop their `Jan…Dec` arrays and take the month abbreviation from `Gregorian.info(moment, Time.FORMAT_MEDIUM)`, which follows the watch language.

### Loading

- Each view loads its strings once (in `initialize`/`onLayout`) into members; `onUpdate` does no resource loading.
- `GlanceView` loads only its two strings. Those two are marked glance-scoped in the resource file so the glance process can reach them. Glance scoping is confirmed with the first glance build on a 32 KB-glance device (fenix 6); if scoping is unsupported on the SDK, the fallback is that all strings are available to the glance, which costs memory but is functionally correct.
- `Util.formatDuration` stays in the `Util` module and keeps a pure core that takes the unit strings as arguments, so it remains unit-testable without resources.

### Default drink names

`DrinkPresets.getDefaults()` reads the 12 names from `Rez.Strings`. It is only called when seeding an empty preset list, so:

- new install → names in the watch language at first launch;
- existing install → nothing changes;
- names are stored as plain text exactly as today (`[name, mg]`), so logs, history and phone sync are unaffected.

### Manifest

`<iq:languages>` gains `fin`, `ces`, `deu`, `fre`.

## Companion page

`companion/settings/index.html` stays a single file.

- Translatable elements carry a `data-i18n` key; placeholders use `data-i18n-placeholder`.
- The script writes one dictionary object per language between marker comments.
- On load the page picks the language from `navigator.language` (first two letters), falls back to English for anything else, sets `<html lang>`, and fills the elements.
- Strings built in script (`Unknown`, `mg`, `-- mg`) come from the same dictionary.
- Dates already use `toLocaleDateString` / `toLocaleTimeString` and need no change.

## Store listing

Prose does not belong in a spreadsheet cell. Each language gets `docs/store-listing.<lang>.md`, mirroring the sections of the English `docs/store-listing.md` (tagline, short description, full description, keywords). Jan pastes these into the Connect IQ store by hand; the store's own length limits (50-char tagline) are noted at the top of each file.

The English listing gains a line: German and French are community drafts, corrections welcome, with the repo link. "Supported Languages" lists all five.

## Translator hand-off

A translator receives two files: `<lang>.csv` and `store-listing.<lang>.md`, plus `translations/README.md`, which explains in one page: fill the `translation` column, keep `$1$` markers, respect `max`, leave brand names alone.

Finnish and Czech sheets go out with the `translation` column empty. German and French sheets are filled by Claude and labelled as drafts.

## Risks and how each is checked

| Risk | Check |
|---|---|
| Long Finnish/German text clipped on round screens | Simulator pass per view in the longest language on the smallest screen (218×218, `fr255s`) and the largest (466×466, `fenix9pro51mm`); tighten `max` in `en.csv` where needed |
| Memory on 64 KB devices (`fenix6`, `fenix6s`, `fr245`, `enduro`) | Compare peak memory in the simulator before and after on `fenix6`; glance on a 32 KB-glance device |
| Czech diacritics missing from a device font | Simulator pass in Czech on one MIP and one AMOLED device |
| Translation drifts from English after later edits | Script marks stale rows; missing keys fail the script |
| Contributor never sees Finnish on real hardware | Sideload build for `fenix9pro51mm` sent before release |

## Testing

- Existing `CaffeineModelTest`, `StorageManagerTest`, `UtilTest` keep passing.
- New `UtilTest` cases for the duration formatter's pure core (hours+minutes, minutes only, zero).
- New `DrinkPresets` test: seeding an empty list yields 12 presets with non-empty names; seeding does not run when a list exists.
- Script self-check: a fixture with a missing key, a dropped placeholder and an over-length string each fail with the right key named.
- Full multi-device `.iq` build succeeds with no new warning kinds.
